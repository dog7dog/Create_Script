CreateScript のプロジェクトは、マニフェスト `createscript.json` を持つディレクトリです。ほかのパッケージを使うプロジェクトには、
ロックファイル `createscript.lock` もあります。ロックファイルは、どのパッケージを使ったかを正確に記録します。

```text
my-app/
  createscript.json
  createscript.lock      (only when there are dependencies)
  src/
    main.cscr
```

## コマンド

```text
$ createscript init my-app
Created my-app/createscript.json
Created my-app/src/main.cscr
Run it with: createscript run my-app/src/main.cscr

$ createscript manifest check my-app
my-app/createscript.json: ok (my-app 0.1.0, entry src/main.cscr, 0 dependencies)

$ createscript lock check my-app
my-app/createscript.lock: not needed (no dependencies)
```

- `createscript init [directory] [--name <name>]` は、`createscript.json` と `src/main.cscr`（「Hello」を出力するプログラム）を作ります。
  ディレクトリに `.gitignore` が無ければ、`/.createscript/` という行を持つ `.gitignore` も作ります（既存の `.gitignore` は、
  その名前のリンクやディレクトリも含めて、決して変えません）。パッケージ名の既定はディレクトリ名です。ディレクトリ名がパッケージ名として
  正しくないときは `--name` を使います。ファイルを上書きすることはありません。どちらかのファイル（またはその名前のリンク）があれば、何も作りません
  （終了コード 73）。各ファイルは、同じディレクトリの一時ファイルに書いてから、ハードリンクで名前を付けます。ハードリンクは、その間に現れた
  ファイルを置き換えずに失敗するので、書きかけのファイルが残ることはありません。ファイルの権限はふつうのもの（umask のとおり）です。
  `src` がシンボリックリンクだったり、ディレクトリでなかったりすれば、何も作りません。そのため `init` がリンクを通して書くことはありません。
  後の手順が失敗したら、`init` は自分が作ったファイルとディレクトリだけを消します（[ロールバック](#init-のロールバック) を参照）。
  ロックファイルは作りません。
- `createscript manifest check [directory]` は、`createscript.json` を確かめ、エントリーのファイルが存在し、通常のファイルで、シンボリックリンクを
  たどった後もプロジェクトのディレクトリの中にあることを確かめます。`createscript.json` そのものも、同じ規則で読みます
  （[プロジェクトのファイルの読み方](#プロジェクトのファイルの読み方) を参照）。
- `createscript lock check [directory]` は、マニフェストを確かめてから、それと照らし合わせて `createscript.lock` を確かめます。
  依存の無いプロジェクトにはロックファイルは要りません。依存があるのにロックファイルが無ければエラーです。

確かめるコマンドは、ファイルを読むだけです。問題は、コンパイルエラーと同じように `file:line:column: error CODE ("arguments")` の形で報告し、
終了コードは 65 です（ファイルが無いか読めなければ 66、使い方の誤りは 64）。引数はファイルから来るので、端末の表示を変えうる文字
（制御文字、双方向テキストなどの書式の文字、行の区切り、対になっていないサロゲート）は `\uXXXX` と表示します。

<!-- ja-only -->
| 終了コード | 意味 |
|---|---|
| 65 | ファイルの内容に問題がある |
| 66 | ファイルが無い、または読めない |
| 64 | 使い方の誤り |
| 73 | `init` がファイルを作れない |

### `init` のロールバック

`init` はファイルを作るとき、ファイルの識別子（`fileKey`。macOS と Linux ではデバイス番号と inode 番号）、大きさ、書いた内容の SHA-256 を
記録します。ディレクトリについては識別子を記録します。後の手順が失敗したら、作ったものを逆の順にたどり、まだ同じものであるときだけ消します。

- ファイルを消すのは、それが通常のファイル（リンクでない）で、大きさと SHA-256 が同じで、両方の識別子が分かるときは識別子も同じ場合だけです。
- ディレクトリを消すのは、それがディレクトリで、識別子が（分かるなら）同じで、空の場合だけです。

それ以外のものは残し、エラーメッセージに挙げます。例：`kept: my-app/createscript.json (it was replaced by another file)`。
ファイルシステムが識別子を返さないとき（`fileKey()` が `null` を返す。一部のファイルシステムやプラットフォーム）は、大きさと SHA-256 だけを比べます。
そのときは、まったく同じ内容の別のファイルに置き換えられても区別できず、消してしまいます。確かめることと消すことは、ファイル名を使った別々の手順なので、
その間の置き換え（確かめた時点と使う時点の競合）は、Java のファイル API では完全には防げません。確かめることで、その隙間をとても小さくしています。

### プロジェクトのファイルの読み方

`manifest check` と `lock check` は、`createscript.json` と `createscript.lock` を次のように読みます。

- シンボリックリンクはたどります。たどった先のファイルは、プロジェクトのディレクトリの中になければなりません（そうでなければ
  `CS_PKG_FILE_OUTSIDE_PROJECT`。`/dev/null` などのデバイスへのリンクも同じ）。壊れたリンクは、ファイルが無いものとして報告します。
- パスの先は通常のファイルでなければなりません。ディレクトリ、FIFO（名前付きパイプ）、デバイス、ソケットは `CS_PKG_NOT_A_REGULAR_FILE` になります。
  FIFO を開くと書き手を待ってしまうので、これはファイルを開く前に確かめます。
- ファイルは本当のパスで、リンクをたどらずに（`NOFOLLOW_LINKS`）開き、大きさの上限より 1 バイト多い分までしか読みません。
  読む前と後で識別子・大きさ・更新時刻を比べます（違えば `CS_PKG_FILE_CHANGED_WHILE_READING`）。

これらの手順は、確かめることと読むことの間の競合を減らしますが、無くすわけではありません。確かめた後にパスの途中のディレクトリが差し替えられることはあり得ますし、
開く直前にファイルが FIFO に差し替えられれば、やはりコマンドは待ってしまいます。`NOFOLLOW_LINKS` が効くのは、パスの最後の部分だけです。
これらのコマンドはファイルを読むだけで、診断に出すのはファイルのごく一部だけです。

## `createscript.json`（スキーマの版 1）

```json
{
  "schemaVersion": 1,
  "name": "example-project",
  "version": "0.1.0",
  "entry": "src/main.cscr",
  "license": "MIT",
  "dependencies": {
    "vector-math": { "version": "1.2.0", "source": "github:owner/vector-math" }
  }
}
```

| 項目 | 必須 | 規則 |
|---|---|---|
| `schemaVersion` | はい | 整数の `1`。ほかの整数は `CS_PKG_UNSUPPORTED_SCHEMA_VERSION` になり、ほかの項目は確かめない（版が違えば意味が違うかもしれないため）。 |
| `name` | はい | パッケージ名：小文字の ASCII の英字と数字で、間に `-` を 1 つずつ挟める。先頭は英字で、64 文字まで（`vector-math`、`app2`）。[Windows で予約された名前](#windows-で予約された名前) は使えない。 |
| `version` | はい | [Semantic Versioning 2.0.0](https://semver.org/)。例えば `1.2.0`、`0.1.0-alpha.1`、`1.0.0+build.5`。先頭の 0 は不可で、128 文字まで。 |
| `entry` | はい | 実行するプログラム。プロジェクトの中の相対パス（下を参照）。 |
| `license` | いいえ | `MIT` や `MIT OR Apache-2.0` のような SPDX のライセンス式（確かめるのは文字と長さだけで、SPDX の一覧とは照合しない）。64 文字まで。 |
| `dependencies` | いいえ | パッケージ名 → `{ "version": 厳密な版, "source": "github:owner/repository" }`。どちらの項目も必須。版の範囲の指定にはまだ対応していない。自分自身には依存できない。1024 個まで。 |

- **知らない項目はエラー** です（`CS_PKG_UNKNOWN_FIELD`）。書き間違えた項目が黙って無視されないようにするためです。
  新しい項目は、新しい `schemaVersion` と一緒に加わります。
- **パッケージ名はモジュール名ではありません。** `import` はモジュール名（`vector_math` のような識別子）を使います。パッケージ名には `-` を使えます。
  2 つは別のもので、一方をもう一方に変換することはありません。パッケージのモジュールの import のしかたは、[パッケージのモジュール](language.md#パッケージのモジュール) で説明しています。
- **エントリーのパス** は、ディレクトリの間を `/` で区切り、`.cscr` で終わらなければなりません。次のものは拒否します：空のパス、絶対パス
  （`/x`、`//server/x`）、`\`、`:`（ドライブ文字と URL）、空の名前（`a//b`、末尾の `/`）、`.` と `..`、ASCII の英字・数字・`.`・`_`・`-` 以外の文字、
  `.` で終わる名前、[Windows で予約された名前](#windows-で予約された名前)（`con.cscr`、`src/NUL.backup.cscr`、`com1/main.cscr`）、
  256 文字より長いパス。`createscript manifest check` は、存在しない・通常のファイルでない・シンボリックリンクでプロジェクトの外へ出るエントリーも拒否します。

### Windows で予約された名前

Windows は、`CON`・`PRN`・`AUX`・`NUL`・`COM0`〜`COM9`・`LPT0`〜`LPT9` を、大文字・小文字を問わず、拡張子が付いても（`con.cscr`、`Nul.txt`、
`com1.tar.gz` はどれもデバイス）デバイスとして扱い、名前の末尾の点と空白を無視します（`con.` や `con ` も同じ）。そのようなファイルは Windows では作れないか、
ファイルの代わりにデバイスを開いてしまいます。プロジェクトとパッケージがどのシステムでも使えるように、これらの名前は macOS と Linux も含めて、
どこでも拒否します（S8.2）。

- `createscript.json`（`name`、`dependencies`）と `createscript.lock` のパッケージ名、`createscript init`（ディレクトリから取った名前も）：
  名前を付けて `CS_PKG_RESERVED_NAME`。
- ライブラリの `modules` のモジュール名（`CS_PKG_RESERVED_NAME`）と、パッケージのアーカイブの中のモジュールのファイル（`modules/con.cscr`。
  非公開のモジュールも。理由を付けて `CS_PKG_ARCHIVE_INVALID_PATH`）。そのため `pack` と `install` は拒否します。
- エントリーのパス（理由を付けて `CS_PKG_INVALID_PATH`）。
- ローカルのモジュールの `import con`。プロジェクトの実行でも、ファイルの実行でも（`CS_MODULE_UNREADABLE`、"'con' is a reserved file name on Windows"）。

そのような名前で始まるだけの名前（`console`、`com10`、`aux-tools`）は使えます。自分の名前が予約された名前である単独のファイルの実行
（`createscript run con.cscr`。v0.1.0-alpha と同じ）は変わりません。アーカイブのパスとモジュール名に使えるのは ASCII の英字・数字・`_`
（と `cscr` の前の `.`）だけなので、Windows のほかの規則（`< > : " / \ | ? *`、制御文字、末尾の点と空白）はそこでは起こり得ず、
大文字・小文字だけが違うパスもすでに拒否しています。Windows そのものでは、まだ試していません。

`createscript init` は、マニフェストを正規形で書きます（上の項目の順、2 文字の空白の字下げ、LF の行末、最後に改行 1 つ、依存は名前の順）。
手で書いたマニフェストは正規形でなくてもかまいません。

## `createscript.json` スキーマの版 2：アプリケーションとライブラリ

> **S8.2 Phase 1**（開発中）。スキーマの版 1 は、今までどおり正しく、変わりません。`createscript init` は今も版 1 を書きます。

```json
{
  "schemaVersion": 2,
  "kind": "library",
  "name": "vector-math",
  "version": "1.2.0",
  "license": "MIT",
  "modules": ["vector_math"],
  "dependencies": {}
}
```

| 項目 | 規則 |
|---|---|
| `kind` | 版 2 では必須：`"application"`（`entry` を持つプログラム）か `"library"`（ほかのプロジェクトが import するパッケージ）。 |
| `entry` | アプリケーションでは必須、ライブラリでは任意。 |
| `modules` | ライブラリだけで、ライブラリでは必須：ほかのプロジェクトが `import` できるモジュール名。1 つ以上、重複なし、1024 個まで。 |

ほかの項目は版 1 の規則のままで、知らない項目は今もエラーです。モジュール名は CreateScript の識別子です：最初は ASCII の英字か `_`、その後は
英字・数字・`_`。`_` だけの名前は不可、32 文字まで、Kotlin のハードキーワードでも、定義し直せない組み込み関数（`println`、`waitTicks`、
`listOf`、`mutableListOf`）でもなく、[Windows で予約された名前](#windows-で予約された名前) でもないこと。**パッケージ名とモジュール名は別のものです**：
パッケージ `vector-math` がモジュール `vector_math` を公開してもよく、一方をもう一方に変換することはありません。ライブラリのモジュール `name` は、
ファイル `modules/name.cscr` にあります。

### 公開モジュールと非公開モジュール

- **公開モジュール** は、`modules` に挙げたものです。そのパッケージに依存するプロジェクトは、これらを `import` できます。
- **非公開モジュール** は、`modules/` にあるほかの `.cscr` ファイルです。これらを import するのは、そのパッケージ自身のモジュールだけを想定しています。
  そのパッケージに依存するプロジェクトは import できません。この規則は `createscript run [directory]` が確かめます
  （S8.2 Phase 4。[パッケージのモジュール](language.md#パッケージのモジュール) を参照）。
- **非公開は秘密という意味ではありません。** 非公開モジュールも公開モジュールと同じくパッケージのアーカイブに入っているので、パッケージを
  ダウンロードした人なら誰でもソースを読めます。「非公開」が制限するのは、ほかのパッケージやプロジェクトが `import` できるものだけです。
  コード・鍵・データを隠す方法ではありません。

## パッケージのアーカイブ：`createscript-package.zip`

> **S8.2 Phase 1**（開発中）。アーカイブの形式と `createscript pack` があります。ダウンロードとインストールは次の段階で加わります。

ライブラリは、`createscript-package.zip` という名前の 1 つの ZIP ファイルとして配布します。タグが `v<version>` の GitHub Release に添付します。
GitHub が自動で作る「Source code」のアーカイブは、パッケージのアーカイブではありません。

```text
createscript-package.zip
  createscript.json          schema version 2, kind "library"
  modules/vector_math.cscr   modules listed in "modules"
  modules/helpers.cscr       other modules of the package
  LICENSE                    optional: LICENSE, LICENCE, NOTICE, README, CHANGELOG or COPYING, also with .md or .txt
```

`createscript pack [directory] [--output <file>]` は、ライブラリのプロジェクトからアーカイブを作ります。入れるのは、ちょうど `createscript.json`、
`modules/` の直下の `.cscr` ファイル、上に挙げた文書だけで、`modules/` にあるそれ以外のもの、シンボリックリンク、通常のファイルでないものは拒否します。
項目はパスの順に、圧縮せず、時刻 1980-01-01 00:00 と権限 0644 で、ディレクトリの項目・コメント・追加の項目を付けずに書きます。そのため、
同じファイルからはいつも同じバイト列になります。結果をインストールと同じ規則で確かめ、SHA-256 を表示し、ファイルを決して上書きしません（終了コード 73）。
コードを実行したりコンパイルしたりはしません。

### 正規形

`pack` が書くバイト列が、アーカイブの **正規形** です。その中身はファイルのパスと内容だけで完全に決まり、機械・ファイルシステム・時刻からは何も取りません。
各ファイルについて、パスの順に（パスは ASCII なので、バイトの順と文字の順は同じ）：

- ローカルヘッダー：シグネチャー `PK\3\4`、必要な版 10、フラグ 0、方式 0（STORED）、時刻 0 と日付 1980-01-01（`0x0021`）、CRC-32、大きさを 2 回、
  名前の長さ、追加の項目なし。その後に名前と内容。

その後に、同じ順で各ファイルのセントラルディレクトリの項目（作成した版 `0x0314`：Unix、ZIP 2.0。必要な版 10、フラグ 0、方式 0、同じ時刻・日付・
CRC-32・大きさ、追加の項目・コメント・ディスク番号・内部属性なし、外部属性 `0100644 << 16`（通常のファイル、権限 0644）、ローカルヘッダーの位置、名前）、
そしてコメントの無いセントラルディレクトリの終わりのレコード。数はすべてリトルエンディアンです。ディレクトリの項目、データディスクリプター、ZIP64 の
レコードなど、ほかのものはありません。

そのため、パッケージのファイルと正規形のアーカイブは、互いに完全に決まります。`install` が受け付けるのは正規形のアーカイブだけです（正しい ZIP ファイルで
中身も正しくても、ほかのツールで作ったもの、例えば圧縮したもの、`modules/` のディレクトリの項目があるもの、時刻や属性が違うもの、コメントのあるものは、
終了コード 65 で拒否します。アーカイブは `createscript pack` で作ってください）。そのおかげで、インストールしたファイルからアーカイブを作り直し、
その SHA-256 を `createscript.lock` と比べられます（[インストールしたパッケージの実行](#インストールしたパッケージの実行s82-phase-4) を参照）。

> [!TIP]
> 正規形のおかげで「インストールしたファイル」と「ロックファイルに記録した SHA-256」を、ダウンロードし直さずに照合できます。

`PackageArchives.read`（`pack` が結果を確かめるときと、`install` が使う）は、この厳密な形のアーカイブだけを受け付けます。ほかのツールが書く
`DEFLATED` の項目と `modules/` のディレクトリの項目も受け付けますが、そのときも `install` はさらに上の正規形を求めます。

- **配置：** セントラルディレクトリの終わりのレコードが最後にあり（コメントは可）、その直前にセントラルディレクトリ、最初のバイトからローカルヘッダーとデータが
  隙間も重なりもなく続くこと。ローカルヘッダーはセントラルディレクトリと一致すること（名前、方式、大きさ、CRC）。前に付けたデータ、項目の間のデータ、
  終わりのレコードの後のデータは拒否し、重なった項目（zip 爆弾を作る既知の方法）も拒否します。
- **対応しないもの：** ZIP64、複数のディスク、暗号化、データディスクリプター、STORED と DEFLATED 以外の圧縮方式。
- **項目：** 名前は表示できる ASCII で、上のパスの規則に従うこと（`..`、絶対パス、`\`、`:`、ほかのディレクトリは不可）。通常のファイルと `modules/` の
  ディレクトリだけを認めます。Unix のファイルの種類がシンボリックリンク・デバイス・FIFO・ソケットの項目は拒否します。重複したパスは、大文字・小文字だけが
  違うものも含めて拒否します。
- **上限：** アーカイブは 32 MiB まで、項目は 1024 個まで、`.cscr` ファイルは 3,000,000 バイトまで（独立版のソースの上限 1,000,000 UTF-16 単位 × 3 バイト。
  `createscript` コマンドのファイルの上限と同じ値）、ほかのファイルは 1 MiB まで、展開した後の合計は 16 MiB まで、圧縮率は 100 倍まで。宣言された大きさを
  展開の前に確かめ、展開は宣言された大きさで止めるので、宣言より大きく展開される項目は拒否します。
- **内容：** `createscript.json` はスキーマの版 2 のライブラリであること（インストールのときは、期待した名前と版であること）。`modules` の各モジュールには
  ファイルがあること。各 `.cscr` ファイルは、バイトオーダーマークの無い正しい UTF-8 で、1,000,000 文字までであること。すべての項目の CRC-32 を確かめます。

パッケージのファイルは、ソースコードと文書だけです。アーカイブもそのマニフェストも、プログラムに、ほかの CreateScript のプログラム以上に OS・ネットワーク・
JVM への権限を与えることはできません。

## パッケージのアーカイブのダウンロード（S8.2 Phase 2）

> **開発中です。** ダウンロード、検査、キャッシュはライブラリ `createscript-install` にあり、`createscript install` が使います
> （[パッケージのインストール](#パッケージのインストールs82-phase-3) を参照）。

依存 `{ "version": "1.2.0", "source": "github:owner/repo" }` のアーカイブは、次の URL にあります。

```text
https://github.com/owner/repo/releases/download/v1.2.0/createscript-package.zip
```

URL は名前から組み立てるので、ダウンロードに GitHub の API の要求は要らず、API の回数制限も受けません。

### 接続

- 使うのは HTTPS だけで、相手は `github.com`、`api.github.com`、GitHub がリリースのダウンロードを転送する先のホスト
  （`release-assets.githubusercontent.com`。`objects.githubusercontent.com` も認める）、ポートは 443 です。この一覧はコードに固定してあり、
  オプション・環境変数・ファイルで、パッケージをダウンロードする先を変えることはできません。
- 転送（リダイレクト）は CreateScript 自身がたどり（最大 5 回）、どの転送先も一覧と照らし合わせます。利用者の情報（`user@host`）、ほかのポート、
  IP アドレス（10 進数や 16 進数の書き方も）、フラグメントを含む URL は拒否します。
- システムのプロキシの設定は使いません（プロキシは後の段階で予定しています）。
- GitHub のトークンは任意で、環境変数 `CREATESCRIPT_GITHUB_TOKEN` からだけ読みます。送るのは `api.github.com` にだけで（ダウンロードや転送先には決して送らない）、
  表示することもありません。メッセージでは URL のクエリーの部分も省きます。リリースのダウンロードでは、そこに署名が入っているためです。
- 上限：接続に 10 秒、本文全体を含めた 1 回の試行に 60 秒、アーカイブは 32 MiB、API の応答は 4 MiB。実際に受け取ったバイト数で数えます
  （それより大きい `Content-Length` は、読む前に拒否します）。止まった接続が 1 回の試行を 60 秒より長く引き留めることはありません。
- やり直し：ネットワークのエラー、時間切れ、HTTP 5xx と 429 の後に、最大 3 回までやり直します。待つのは 1、2、4 秒か、`Retry-After` や回数制限の
  リセットが示す時間です（それが 60 秒より長ければ、CreateScript はあきらめてトークンの利用を勧めます）。HTTP 404、401、ほかの 403 の応答はやり直しません。

### 信頼

| 何を | 信頼する相手 | 示すこと | 示さないこと |
|---|---|---|---|
| `createscript.lock` の SHA-256 | あなたのプロジェクト | アーカイブが、前に記録したものとまったく同じであること。**ほかのアーカイブは必ず拒否する** | 記録したものが良いものだったか |
| ロックファイルに記録の無い最初のダウンロード（TOFU） | HTTPS と、その時点でリポジトリを管理している人 | アーカイブが途中で変えられていないこと | 誰が書いたか、アカウントが乗っ取られていないか |
| アセットの GitHub の `digest`（API から） | GitHub（ダウンロードと同じ相手） | GitHub とあなたの間でファイルが壊れたり差し替えられたりしていないこと。**値が違えば拒否する** | 作者については何も示さない。API を使えないとき（回数制限、ネットワーク、digest が無い）は、ダウンロードを **未検証** と報告し、理由を示す |
| リリースの `immutable`（API から） | GitHub | 公開した後に、リリースのアセットを差し替えられないこと | 公開した時点で良いものだったか |
| キャッシュ | 誰も信頼しない | — | 読むのはロックファイルが SHA-256 を示すときだけで、その SHA-256 を毎回確かめる |

> [!NOTE]
> 表の要点：ロックファイルに SHA-256 を記録したら、**ほかのアーカイブは必ず拒否します**（ただし、記録したものが良いものだったかは示しません）。最初のダウンロードだけは、
> その時点のリポジトリを信頼するしかありません（TOFU：Trust On First Use）。

署名付きの index を持つ公式のレジストリでの、審査済みのハッシュは、S8.3 で作っています（[registry.md](registry.md) を参照）。クライアントの側はできています
（Phase 3：`createscript install <name>@<version>`、直接のインストールと復元の審査状況）。しかし、**公式のレジストリはまだ公開しておらず、本番の鍵も無く、
メンテナーを募集しています**。それまで `createscript install <name>@<version>` は通信せずに拒否し（終了コード 69）、直接のインストールは、
審査状況を確かめられなかったと報告します。index をダウンロードできないとき、`--offline` を付けない限り、`createscript` は前に保存した index に戻りません
（S8.3 Phase 5）。そのため、ダウンロードを妨げることで、取り除いたパッケージをこっそり復活させることはできません。`createscript.lock` からの復元には影響しません。
パッケージの作者自身による署名は、まだ予定していません。

### キャッシュ

アーカイブは SHA-256 ごとに、`CREATESCRIPT_CACHE_DIR` の下の `archives/sha256/<sha256>.zip` に保存します。既定の場所は、macOS では
`~/Library/Caches/CreateScript`、ほかでは `$XDG_CACHE_HOME/createscript` か `~/.cache/createscript` です。CreateScript がそこに作るディレクトリは、
その利用者だけのものです（権限 0700）。キャッシュの場所そのものはシンボリックリンクでもかまいません（例えば別のディスクへ）。しかし `archives`・`sha256`・
各項目はリンクであってはなりません。リンクや、内容が名前と合わない項目は、使わず、消さず、置き換えもせず、キャッシュを使わずに警告付きでダウンロードを続けます。
キャッシュの中のものを実行することは決してありません。

## `createscript.lock`（ロックの版 1）

ロックファイルは、手ではなくツールが書きます（S8.2 から）。プロジェクトが使うパッケージを正確に記録するので、同じロックファイルからは、いつも同じパッケージになります。

```json
{
  "lockVersion": 1,
  "root": {
    "name": "example-project",
    "version": "0.1.0"
  },
  "packages": [
    {
      "name": "vector-math",
      "version": "1.2.0",
      "source": "github:owner/vector-math",
      "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef",
      "dependencies": []
    }
  ]
}
```

| 項目 | 規則 |
|---|---|
| `lockVersion` | 整数の `1`（ほかの整数は `CS_PKG_UNSUPPORTED_LOCK_VERSION`）。 |
| `root` | プロジェクトの `name` と `version`。`createscript.json` のものと同じでなければならない。 |
| `packages` | 直接・間接に使うすべてのパッケージ。`name` の順に並べる。4096 個まで。 |
| `packages[].name`, `version`, `source` | マニフェストと同じ規則。 |
| `packages[].sha256` | パッケージのアーカイブの SHA-256：ちょうど 64 桁の小文字の 16 進数（大文字は拒否するので、ファイルの形は 1 つに決まる）。 |
| `packages[].dependencies` | このパッケージが直接使うパッケージの名前。並べ替え、重複なし。どれも `packages` になければならない。1024 個まで。 |

### パッケージの識別

- 1 つのロックファイルの中では、パッケージを **名前** で識別します。各名前は 1 回だけ現れます。プロジェクトは、各パッケージの 1 つの版を、1 つの取得元から使います。
- `version` と `source` は、その名前のどのリリースを使い、どこから取るかを示します。`sha256` は、パッケージのアーカイブのバイト列そのものを識別します。
- 依存は、パッケージを名前で参照します。依存の循環はエラーです（`CS_PKG_LOCK_DEPENDENCY_CYCLE`）。
- 2 つの依存が、同じ名前を違う版や違う取得元で必要とするのは衝突です。そのような衝突の解決や報告は、依存の解決（S8.2 以降）の役目です。

### 正規形

ロックファイルの内容に対して、正しいバイト列はちょうど 1 つです：バイトオーダーマークの無い UTF-8、上に示した項目の順、パッケージとその依存は名前の順、
2 文字の空白の字下げ、キーと値の間は `": "`、LF の行末、最後に改行 1 つ。文字列でエスケープするのは `"`、`\`、制御文字だけです。
`createscript lock check` は、ほかの形を、内容が同じでも、最初に違う行と一緒に `CS_PKG_LOCK_NOT_CANONICAL` として報告します。
こうすると、ロックファイルを再現でき、その変更をレビューしやすくなります。

### マニフェストとの整合

`createscript lock check` は次のものを報告します。

- `CS_PKG_LOCK_ROOT_MISMATCH`：`root` がマニフェストの `name` や `version` と違う。
- `CS_PKG_LOCK_MISSING_PACKAGE`：マニフェストの依存がロックファイルに無い。
- `CS_PKG_LOCK_VERSION_MISMATCH` / `CS_PKG_LOCK_SOURCE_MISMATCH`：パッケージの版や取得元が、マニフェストが求めるものと違う。
- `CS_PKG_LOCK_UNUSED_PACKAGE`：マニフェストの依存からたどり着けないパッケージ。
- `CS_PKG_LOCK_DUPLICATE_PACKAGE`、`CS_PKG_LOCK_DUPLICATE_DEPENDENCY`、`CS_PKG_LOCK_UNKNOWN_DEPENDENCY`、`CS_PKG_LOCK_DEPENDENCY_CYCLE`：
  ロックファイルの中の問題。

`createscript lock check` は、SHA-256 の形だけを確かめます。何もダウンロードしないので、比べるアーカイブが無いからです。
`createscript install` はダウンロードしたかキャッシュにあるアーカイブと、`createscript run [directory]` はインストールしたファイルから作り直したアーカイブと、
この SHA-256 を比べます（[インストールしたパッケージの実行](#インストールしたパッケージの実行s82-phase-4) を参照）。

## JSON の規則（両方のファイル）

- RFC 8259 のとおりの厳密な JSON：コメント、末尾のカンマ、単一引用符、引用符の無いキー、`NaN` はどれも使えません。
- **重複したキーは、どの深さでもエラー** です（`CS_PKG_JSON_DUPLICATE_KEY`）。最後の値が黙って勝つことはありません。`{"a": 1, "a": 2}` も重複です。
- 数は 64 ビットに収まる整数でなければなりません（小数や指数は不可）。それ以外を必要とする項目はありません。
- 文字列に、生の制御文字や対になっていないサロゲートを含めてはいけません。
- UTF-8 だけです。バイトオーダーマークは拒否し（`CS_PKG_BYTE_ORDER_MARK`）、正しくない UTF-8 も拒否します。
- 大きさの上限：`createscript.json` は 64 KiB、`createscript.lock` は 1 MiB、入れ子は 16 段まで。コマンドは上限より 1 バイト多い分までしか読まないので、
  巨大なファイルを最後まで読むことはありません。
- JSON の構文エラーの後は、ほかに何も確かめません。それ以外の問題は、すべて報告します（最大 64 件）。

### 自前の小さな構文解析器を使う理由

CreateScript のビルドには JSON のライブラリがありません。JVM でよく使われる選択肢を検討しました：kotlinx.serialization（ライブラリに加えて Gradle の
コンパイラープラグインが要る）、Jackson（大きなライブラリ。重複したキーを拒否できるが、その機能を有効にしたときだけ）、Gson と org.json（小さいが、
重複したキーを拒否するか最後の値が勝つかが API と版によって違う）。どれを選んでもパッケージと他者のライセンスの告知に依存が増え、しかも選んだ版の
正確な挙動を確かめなければなりません。プロジェクトのファイルが JSON に求めることはとても少なく、大きさと入れ子の固定の上限、すべてのエラーの行と列、
重複したキーの必ずの拒否が欲しいのです。そこで `createscript-project` は、自前の厳密な構文解析器と書き出し器（`Json.kt`、約 400 行、再帰を使わないので
深い入れ子でもスタックを使い果たさない）を持ち、上のケースでテストしています。ライブラリについての記述は、私たちの知る範囲の文書に基づくもので、
S8.1 で実際に動かしてはいません。

## コードの構成

- `createscript-project`（新しい Gradle のモジュール）：JSON の構文解析器と書き出し器、マニフェストとロックファイルのモデル、その規則、正規形と整合の検査、
  パッケージのアーカイブの読み取りと書き出し（`PackageArchives`）、レジストリの形式、正規形の index とその Ed25519 の署名の検査
  （`project.registry`、S8.3 Phase 1。[registry.md](registry.md) を参照）。Kotlin の標準ライブラリと JDK だけを使い、ファイルにもネットワークにも触れません。
  バイト列を受け取り、値と診断を返します。
- `createscript-install`（S8.2 Phase 2 と 3）：JDK の HTTP クライアントで GitHub Releases からパッケージのアーカイブをダウンロードし、その SHA-256 と GitHub の
  digest を確かめ、キャッシュを管理し、依存を解決し、ジャーナルを使ってインストールします。ダウンロードしたものを実行することは決してありません。
  S8.3 Phase 3 でレジストリのクライアント（`RegistryTrust`、`RegistryClient`、`RegistryCache`、`RegistryReview`）が加わりました：署名付きの index を
  ダウンロードして検証し、受け入れた index とその履歴を保存し、インストールしたものの審査状況を確かめます
  （[registry.md](registry.md#クライアントcreatescript-install-nameversionphase-3)）。
- `createscript-registry-tool`（S8.3 Phase 2）：レジストリのプルリクエストと承認を確かめ、計画中のレジストリのための index を作り、署名し（今はテスト用の鍵だけ）、
  確かめ、検証します（[registry.md](registry.md)）。`createscript` のパッケージには含まれません。
- ビルドは、すべての依存とプラグインを `gradle/verification-metadata.xml` と照らし合わせて検証します（SHA-256、strict。S8.3 Phase 5）。依存を変えたら、
  `./gradlew --write-verification-metadata sha256 build installDist` で作り直し、差分を確認してください。
- `createscript-cli`：ファイルを読み書きし、ディスク上のエントリーのファイルを確かめ、`init`・`manifest check`・`lock check`・`pack`・`install`
  （`install <name>@<version>` を含む）を実装します。
- `createscript-core`（言語、コンパイラー、仮想機械）：言語と仮想機械は変わっていません。S8.2 Phase 4 で、ホストが import を制御する方法が 2 つ加わりました。
  `ModuleAccess` と、`ScopedModuleResolver` を使う `CreateScript.compileScoped` です（[パッケージのモジュール](language.md#パッケージのモジュール) を参照）。
  Core は今もファイルを読まず、ネットワークも使いません。

## パッケージのインストール（S8.2 Phase 3）

> **開発中です。** インストールしたパッケージは `createscript run [directory]` が使います（S8.2 Phase 4。
> [プロジェクトを実行する](cli.md#プロジェクトを実行する) と [パッケージのモジュール](language.md#パッケージのモジュール) を参照）。
> `createscript install <name>@<version>`（署名付きのレジストリの index から名前でインストールする。S8.3 Phase 3）も同じインストーラーを使います。
> それは [registry.md](registry.md#クライアントcreatescript-install-nameversionphase-3) で説明しており、公式のレジストリを公開するまでは動きません。

```text
$ createscript install github:owner/vector-math@v1.2.0
Installed numbers 3.0.0 from github:owner/numbers -> .createscript/packages/numbers/3.0.0
  sha256 9c1e…
  downloaded; recorded on first use (trust on first use); GitHub digest matched; the release is immutable
Installed vector-math 1.2.0 from github:owner/vector-math -> .createscript/packages/vector-math/1.2.0
  sha256 3f1c…
  downloaded; recorded on first use (trust on first use); GitHub digest matched; the release is immutable
Updated createscript.json (dependency vector-math 1.2.0 from github:owner/vector-math)
Wrote createscript.lock (2 packages)

$ createscript install              # install what createscript.json and createscript.lock say
$ createscript install --offline    # the same without the network (from the cache only)
```

> [!NOTE]
> 上の例の最後の 2 行の意味：`createscript install` は「`createscript.json` と `createscript.lock` に書いてあるものをインストールする」、
> `createscript install --offline` は「同じことを、ネットワークを使わずに（キャッシュだけから）行う」です。

- `createscript install github:<owner>/<repo>@v<version> [directory]` は、パッケージをダウンロードし、その `createscript.json` から名前を読み、
  `dependencies` のその 1 つの項目を加えるか変えて、すべてをインストールします。受け付けるのは厳密な版だけです（`@v1.2.0` か `@1.2.0`）。
  別の取得元の同じ名前の依存は置き換えず、1 つの取得元が 2 つのパッケージになることもありません。
- `createscript install [directory]` は、`createscript.json` の依存をインストールします。`createscript.lock` が同じ名前・版・取得元で持っている
  パッケージには、その SHA-256 を使い、それを **必ず** 守らせます（キャッシュからでも GitHub からでも、違うアーカイブは拒否する）。
  ほかのパッケージは、最初に使うときに記録します。もう要らないロックファイルの項目は、ロックファイルから消します。
- `--offline` はネットワークを使いません。どのパッケージも、ロックファイルの SHA-256 でキャッシュになければなりません。
- 同じコマンドをもう一度実行しても、何も変わりません（どのファイルも書き直しません）。
- 終了コード：69 はネットワークを使えない（または `--offline` でキャッシュに無い）、65 はパッケージの問題・衝突・正しくないプロジェクトのファイル、
  66 は `createscript.json` が無い、73 はファイルが想定した状態でない（シンボリックリンク、変わったファイル、終わらせることも元に戻すこともできない
  中断したインストール）、75 は別のインストールが動いている。

### 依存

- 依存は `createscript.json` から、名前の順に深さ優先でたどります。そのため、ダウンロードの順と結果は、ファイルだけで決まります。
- 各名前は 1 つのパッケージです。同じ名前への 2 つの要求は、版も取得元も同じでなければなりません。そうでなければ、両方の要求と、それを出したものを示して
  インストールを止めます（版を選んだり、まとめたりはしません。範囲と解決は S8.4 で予定しています）。1 つの取得元が 2 つのパッケージになることはなく、
  プロジェクト自身に依存するパッケージもあり得ません。
- 循環は拒否します（`dependency cycle: alpha -> beta -> alpha`）。
- 1 回のインストールの上限：パッケージ 256 個、深さ 32、パッケージのファイルは合計 128 MiB（各アーカイブには、さらに
  [アーカイブの上限](#パッケージのアーカイブcreatescript-packagezip) があります）。
- どのアーカイブも `createscript pack` と同じように確かめます：ライブラリであること、期待した名前と版、認められたパスだけ、正しい取得元。
  あるパッケージについて、`createscript.lock` がアーカイブと違う依存を挙げていれば、ロックファイルが手で変えられたということなので、インストールを止めます。

### ファイル

```text
.createscript/
  install.lock                       held while an installation runs (an empty file)
  packages/<name>/<version>/         an installed package: createscript.json, modules/*.cscr, documents
    .createscript-package.json       the marker: which installation put the files there and their SHA-256
  transaction.json                   only while an installation is running or after it was interrupted
  txn-<id>/                          the prepared files of that installation
```

<!-- ja-only -->
| パス | 役割 |
|---|---|
| `install.lock` | インストールの間に保持するロック（空のファイル） |
| `packages/<name>/<version>/` | インストールしたパッケージ |
| `.createscript-package.json` | 印（marker）：どのインストールがファイルを置いたかと、その SHA-256 |
| `transaction.json` | インストールの最中か、中断した後にだけある |
| `txn-<id>/` | そのインストールが準備したファイル |

- `.createscript/` はコミットしないでください。`createscript init` は、ディレクトリに `.gitignore` が無ければ `/.createscript/` を書いた `.gitignore` を作ります。
  既存の `.gitignore`（その名前のリンクやディレクトリも）は決して変えません。`install` は、その行が無ければ加えるよう勧めますが、自分で `.gitignore` を変えることはしません。
- 既存の `packages/<name>/<version>/` を使うのは、その印とファイルがパッケージと正確に一致し（足りない・余分な・変わったファイルが無く、シンボリックリンクも無い）、
  そのファイルから作り直した正規形のアーカイブがパッケージの SHA-256 を持つときだけです。そうでなければ、何も変える前にインストールを止め、そのディレクトリを
  消すよう求めます。
- もう使われない版のディレクトリは消しません（パッケージの削除は、後の段階で予定しています）。
- `createscript.json`、`createscript.lock`、`.createscript` とその中のすべては、シンボリックリンクであってはなりません。`install` はリンクを通して書きません。
- **インストール中に差し替えられたディレクトリ（L-5）。** Java 21 はファイルをパスで指すので、同じ利用者として動くほかのプログラムが、確かめてから書くまでの間に、
  パスの途中のディレクトリをリンクに差し替えられます。そこで macOS と Linux では、`install` はプロジェクトの中のファイルを、小さな補助プロセスを通してだけ変えます
  （固定のスクリプトを持つ `/bin/sh` と、標準の `stat`・`mkdir`・`link`・`unlink`・`mv`・`rmdir`・`chmod`・`head` のコマンド。名前は引数として渡して確かめ、
  スクリプトの中に入れることはありません）。
  - 補助プロセスはプロジェクトのディレクトリで始まり、そのデバイスと inode を確かめます。対象のディレクトリへ 1 段ずつ入り、そこから `..` をたどると
    プロジェクトのディレクトリへ戻ることを確かめます。その後、作業ディレクトリはシステムが保持するので、後でパスの途中のディレクトリを差し替えても、
    向き先は変わりません。
  - そのディレクトリの中の、1 つの名前だけを扱います。新しいファイルは排他的に作り、開いたファイルが新しい空のファイルでリンクが 1 つであることを確かめてから
    書きます。名前は `link`（決して置き換えない）か `mv -h` / `mv -T`（リンクの中に入らない）で付けます。権限は開いたファイルを通して変えます。
    削除には、リンクそのものを消す `unlink` と `rmdir` を使います。
  - ディレクトリの間で何かを移すことはありません。パッケージのディレクトリは `.createscript/packages/<name>/.placing-<id>` として書いてから、その場で名前を変えます。
    `createscript.json`、`createscript.lock`、ジャーナルも、最終的な名前の隣に書いてから、その場で名前を変えます。
  - 補助プロセスが 60 秒以内に応えなければ止め、インストールは失敗します。
  - Windows（`/bin/sh` が無い）では、以前のパスに基づく確かめ方を使い、そこでは競合を防げません。
  - オプトインの競合のテスト（`CREATESCRIPT_L5_RACE=1`、`L5RaceTest`）は、インストール中にディレクトリを差し替え、リンクの先にインストーラーの名前の
    ファイルも置きます。`AnchoredFsTest` は、決まった時点で差し替えます。
- ダウンロードしたものを実行することはありません。アーカイブは確かめて、ファイルとして展開するだけです。

### 複数のファイルを安全に変える

1. `.createscript/install.lock` を保持します（`FileChannel.tryLock`）。そのため、1 つのプロジェクトで動くインストールは 1 つだけです。
   このファイルには、ロックする範囲が 2 つあります：門（バイト 0）とデータ（残り）。`install` は門を排他的に取り、次にデータを排他的に取ります。
   `run` は門を共有で取り、次にデータを共有で取り、すぐに門を放します。インストールが門を持って待っている間は、新しい run は確かめ始められないので、
   次々に来る run がインストールを締め出すことはできません。どちらも先に門を取るので、互いに輪になって待つこともありません。`install` は最大 30 秒、
   `run` は最大 10 秒待ちます（その後は終了コード 75）。ロックは 20 ミリ秒ごとに試し直し、待っている複数のプログラムの間に順番はありません。
2. プロジェクトのファイルを読み、すべてのパッケージをダウンロードして確かめます。ここまではプロジェクトの中は何も変わらないので、ネットワークや検査の失敗では、
   すべてが元のままです。
3. 新しい `.createscript/txn-<id>/` を作り、その中にまず `journal.tmp` を書きます：完全なジャーナル（状態 `prepared`）で、古いマニフェストとロックファイル、
   新しいマニフェストとロックファイル、各パッケージの印の SHA-256 を持ちます（印はまずメモリーの中で作ります）。次に、新しいマニフェストとロックファイル、
   今のものの写し、展開したパッケージ（各パッケージの印が先、その後にファイル）を書き、ディスクに書き出します。
4. ジャーナルを公開します：`journal.tmp` に、決してファイルを置き換えないハードリンクで `.createscript/transaction.json` という名前を付けます。
   ファイルシステムにハードリンクが無い場合（例えば FAT）は、その名前が空いていることを確かめて、原子的な移動（`ATOMIC_MOVE`）で名前を変えます。
   その間、`install.lock` がほかのインストールを遠ざけます。どちらもできなければ、インストールを止め、何も変えません。ジャーナルを写すことは決してないので、
   書きかけの `transaction.json` が現れることはありません（すべての項目を持つ完全な JSON でないものは拒否します）。
5. パッケージを `packages/` に移し（決してディレクトリを置き換えない）、次に `createscript.json` と `createscript.lock` を置き換えます（名前の変更）。
   それぞれを置き換える前に、今のファイルが手順 2 で読んだものと同じ SHA-256 で、ファイルシステムが示すなら同じファイル（`fileKey`）でなければなりません：
   ほかのプログラムが変えたり置き換えたりしたファイルを上書きすることはありません。各パッケージを移す前に、プロジェクトから `packages/<name>` までの
   どのディレクトリも、本当のパスがあるべき場所にある本物のディレクトリ（シンボリックリンクでない）でなければなりません。移した後は、パッケージがそこに
   なければなりません：`packages/<name>` がまだそのディレクトリで（同じ `fileKey`）、パッケージのディレクトリが移したもので（同じ `fileKey`）、
   このインストールの印とファイルを持つこと。`createscript.json` を置き換える直前に、すべてのパッケージをもう一度確かめます。どれかの検査が失敗したら、
   インストールを完了せずに元に戻します。シンボリックリンクの先のものは、読みも、変えも、消しもしません。
6. ジャーナルを `committed` にし、準備したファイルとジャーナルを消します。

手順が失敗したら、インストールはすぐに元に戻ります。プロセスが止まったとき（クラッシュや `kill`）は、次の `createscript install` がジャーナルを見つけ、
ほかのことをする前に、そのインストールを終わらせるか元に戻します。

- **ジャーナルは信頼しません。** この利用者の通常のファイルで、期待したとおりの項目と正しい値を持たなければなりません。パッケージ名・版・ID を確かめるので、
  `.createscript` の外のパスを指すことはできません。
- **ここで書かれたものでなければなりません。** ジャーナルは、書かれた場所を記録します：プロジェクトの本当のパスと、`.createscript` と `txn-<id>` の
  ファイルの識別子（`fileKey`）です。自動で使うのは、その 3 つが今も同じときだけです。写した・展開した・ダウンロードした・移した・バックアップから戻した
  プロジェクトは、ディレクトリが新しくなる（またはパスが変わる）ので、一緒に来たジャーナルを自動で使うことは決してなく、下に書いたようにコマンドは止まります。
  ファイルシステムに `fileKey` が無いところ（例えば Windows の NTFS では Java が返さない）では、中断したインストールを自動で終わらせたり元に戻したりすることは
  決してありません。中断していないインストールと、同じプロセスがすぐに元に戻す失敗は、いつもどおりに動きます。以前の版のジャーナル（この記録を持たない）も、
  自動では使いません。
- **書くものは、毎回確かめます。** 記録した場所は証明にはならない（下を参照）ので、終わらせる前に：新しいマニフェストは、古いものか、古いものに依存を 1 つ
  加えるか変えたもの（`install` がする唯一の変更）でなければなりません。新しいロックファイルは、それに対して `lock check` に合格しなければなりません。
  古いロックファイルが同じ名前・版・取得元で持つパッケージは、SHA-256 と依存を保たなければなりません。置くべきすべてのパッケージは、新しいロックファイルの
  SHA-256 を持つ正規形のアーカイブを作り直せなければなりません。元に戻す前には、保存した古いマニフェストとロックファイルが正しく、同じように新しいものと
  合っていなければなりません。検査が失敗したら、何も変えずに、下に書いたようにコマンドは止まります（反対の方向に切り替えることはしません）。
- **終わらせる** のは、新しいマニフェストとロックファイルが置かれているかその写しが無傷で、すべてのパッケージがこのインストールの印と一緒に置かれているか、
  その準備した写しが無傷なときです。
- それ以外は **元に戻します**：SHA-256 が新しいものであるマニフェストやロックファイルは、写しから戻します（写しが無ければ消します）。このインストールの印を持ち、
  ファイルが変わっていないパッケージのディレクトリは消します。
- **ほかの人が変えたファイルを、上書きしたり消したりすることは決してありません。** 古いものでも新しいものでもないマニフェストやロックファイル、
  合わないパッケージのディレクトリは、そのままにします。それ以外は元に戻し、残したものの一覧を示して止まります。
- **どちらも安全でないとき**（壊れたジャーナル、写しが無いか変わっている）は、何も変えません。コマンドは理由を示し、インストールが残したファイル
  （`transaction.json` と、中身を含む `txn-<id>/`）を挙げ、`createscript.json` と `createscript.lock` がインストールの前の版か後の版か、ほかの人が変えたものかを伝え、
  手で確かめる手順を挙げます：保存した写し（前は `*.old`、後は `*.new`）と比べ、そのトランザクションのパッケージのディレクトリを確かめ、その後で初めて
  ジャーナルと `txn-<id>/` をプロジェクトの外へ移し（確信が持てるまで取っておく）、もう一度 `createscript install` を実行します。ファイルを確かめる前に
  ジャーナルを消すよう求めることは決してありません。
- ジャーナルがある間、`manifest check`・`lock check`・`pack` は終了コード 65 で止まります。
- 手順 4 より前に止まったインストールは、何も変えていません。その `txn-<id>` のディレクトリは、次の `createscript install` が消します（そう報告します）。
  ただし、ジャーナルが無く、中のすべてが始めたときの記録と合うときだけです：ディレクトリとそのファイルとサブディレクトリがシンボリックリンクでなく、
  この利用者のもので、名前が `txn-` と UUID で、`journal.tmp` がその ID の正しいジャーナルで、ほかのファイルはどれも、記録が挙げる写しか準備したパッケージで、
  記録した SHA-256 を持つこと（まだ書いていなかったファイルは無くてもかまいません）。何かを消す前に、すべてを確かめます。それ以外のものはその場に残し、
  理由と一緒に報告します。例えば、変わったファイル、`install` が作らないファイル、シンボリックリンク、`journal.tmp` の無いディレクトリ（終わった・元に戻した
  インストールが、いくつかのファイルを確かめて消せなかったときに残すもの、または以前の版が作ったもの）です。
- **書いている最中だったファイル。** `txn-<id>/` のどのファイルも（`journal.tmp` が最初）一時的な名前で書き、完全に書いてディスクに書き出した後で初めて
  自分の名前を得ます。そのため、自分の名前を持つファイルが一部だけということはありません。一時的な名前は、まず `.part-<UUID>`（まだ空）、次に
  `.part-<inode>-<size>-<name>` で、ファイルそのもの（inode）と、どれだけの大きさになるかを記録します。ファイルは所有者の読み取り専用（`r--------`）で作り、
  それを作った記述子を通してだけ書くので、ほかの書き込み（追記、上書き、その場で保存するエディター）は拒否されます。最終的なファイルは、名前を得た後に
  `rw-r--r--` になります。止まったインストールは、そのようなファイルを 1 つ残すことがあります。次のインストールがほかのものと一緒に消すのは、それがこの利用者の
  もので、通常のファイル（リンクでない）で、まだ読み取り専用で、まだ `install` が作ったファイルで（同じ inode。新しいファイルに保存するエディターはこれを変える）、
  記録より大きくなく、記録が期待し、まだ存在しない名前のためのものであるときだけです（空の `.part-<UUID>` は何も持たないので消してよい）。各ファイルを消す直前に、
  その SHA-256 とファイルの識別子（`fileKey`）が、確かめたときのままでなければなりません。それ以外の `.part-` のファイルは残して報告します。そのファイルは
  書き終わっていないので内容は確かめられず、編集を防ぐのは読み取り専用の権限です。記録した大きさの中で、ファイルを書き込み可能にしてまた読み取り専用に戻す
  （`chmod`）人、すでに書き込み用に開いていたプログラム、`root` による変更は防げません。ファイルを消すとその名前だけが消えるので、ファイルにほかの名前
  （ハードリンク）があれば、内容は残ります。
- どの `createscript install` も、`.createscript/packages/<name>/<version>/` も見て、使えないディレクトリをそれぞれ報告します：印と合わないファイル
  （ソースか印が変えられた、ファイルが足りない・余分、印が壊れているか無い）、別のパッケージや版を指す印、もう印にあるアーカイブを作れないファイル、
  シンボリックリンク（報告するだけで、決してたどらない）、`install` が作らない名前。これで例えば、中断して元に戻したインストールの後に編集された
  パッケージのディレクトリが見つかります。警告はディレクトリと理由を示し、自分の変更の写しを取ってからディレクトリを消すよう求めます。何も消さず、直さず、
  たどりもせず、この検査でインストールが失敗することもありません（読めないディレクトリも報告します）。`createscript.lock` がもう挙げていない版の、
  使えるディレクトリは報告しません（その削除は予定しています）。`.` で始まる名前（`.DS_Store` など）は飛ばします。このインストールに必要なディレクトリは、
  これまでどおりインストールを止めます。
- **ジャーナルの一時ファイル。** ジャーナルは `txn-<id>/journal.tmp` を通して書き直します（`committed` へ）。それを書いている最中にプロセスが止まったら、
  次のインストールはほかの何よりも先にそのファイルを消します。ただし、それがこの利用者の通常のファイル（リンクでない）で、このトランザクションの完全な
  ジャーナルか、その始めの部分であるときだけです（ジャーナルのバイト列は内容から決まるので、一部だけ書かれたファイルは必ずその始めの部分になります）。
  意味を持つジャーナルは `transaction.json` です。それ以外の `journal.tmp` があると、何も変えずにコマンドは止まり、最初の手順は、そのファイルを
  プロジェクトの外へ移すことです。
- **トランザクションのディレクトリが無いとき。** `transaction.json`（状態 `prepared`）が存在しない `txn-<id>` のディレクトリを指していれば、コマンドはそう伝えて
  止まります。そのディレクトリを移したのなら戻すか、2 つのファイルを自分で確かめてください。
- 復旧の後に動くインストールが失敗しても（例えば `--offline` でパッケージがキャッシュに無い）、そのメッセージは、中断したインストールを先に終わらせたか
  元に戻したことを伝えます。

これらの手順の分かっている限界：`install` は、`createscript.json`、`createscript.lock`、消すファイルを確かめ（SHA-256 と、ファイルシステムが示すなら `fileKey`）、
その後の別の手順で置き換えたり消したりします。そのため、その間の瞬間に、あなたの利用者として動くプログラムがそのファイルを変えても、いつも気付けるとは限りません。
macOS と Linux では、補助プロセスは確かめたディレクトリの中で働き続けるので、そのような変更で手順の向き先がプロジェクトの外へ変わることはありません（下の L-5 を参照）。
ただし、ファイルは名前で置き換え、そのときにもう一度は確かめません。ファイルシステムに `fileKey` が無いところでは、内容と大きさが同じ別のファイルに置き換えられても
区別できません。Windows では試していません。`run` にはこの隙間はありません：確かめたバイト列をそのままコンパイルします。

#### 中断したインストールを手で確かめる

`createscript install` が "cannot be finished or undone safely" で止まったとき、何も変えていません。メッセージは、理由、残したファイル、
`createscript.json` と `createscript.lock` がインストールの前の版か後の版かを挙げます。その後：

1. メッセージの最初の手順が具体的なら、そのとおりにします（例えば、`journal.tmp` をプロジェクトの外へ移す、移された `txn-<id>` のディレクトリを戻す）。
2. `createscript.json` と `createscript.lock` を、`.createscript/txn-<id>/` に保存した写し（インストールの前は `*.old`、後は `*.new`）と比べ、
   使いたい版を残します。`createscript manifest check` と `createscript lock check` で、それが正しいかが分かります。
3. `.createscript/transaction.json` と `.createscript/txn-<id>/` をプロジェクトの外へ移し（確信が持てるまで取っておく）、もう一度 `createscript install` を
   実行します。すべてのパッケージを `createscript.lock` ともう一度照らし合わせ、使えないパッケージのディレクトリを報告します。

> [!CAUTION]
> 2 つのファイルを確かめる前に、ジャーナルを消さないでください。ジャーナルがある間は、`run`・`manifest check`・`lock check`・`pack` が動くのを拒みます。
> こうして、途中までしか終わっていない更新を間違って使うことを防いでいます。

これが守るもの：ほかの人が作ったプロジェクトに、その人が選んだジャーナルと保存した写しを入れた `.createscript` があって、次の `createscript install` が、
あなたがレビューした `createscript.json` と `createscript.lock` を置き換えてしまう場合です。そのようなジャーナルは、そのディレクトリがあなたのコンピューターの
そのパスで作られたものではないので、使いません。守らないもの：あなたの利用者として動き、プロジェクトのファイルを変えられるプログラムです。それはファイルの識別子を
読み、合うジャーナルと、依存を加えたり変えたりしたように見える保存した写しを書けます。`createscript.lock` を直接変えることもできます。ファイルの識別子は秘密でも
署名でもなく、ここで書かれたジャーナルと、ファイルと一緒に来たジャーナルを見分けるだけです。

### インストールしたパッケージの実行（S8.2 Phase 4）

`createscript run [directory]` は、コンパイルの前に、インストールしたパッケージを `createscript.lock` と照らし合わせて確かめ（[プロジェクトを実行する](cli.md#プロジェクトを実行する) を参照）、
そのソースを既存の `ScopedModuleResolver`（`CreateScript.compileScoped`）を通してコンパイラーに渡します。そのため、Core は今もファイルもネットワークも読みません。
各 `import` は、それを書いたファイルのスコープの中で探し、パッケージのモジュールには `package/module` という ID を付けるので、別々のパッケージの同じモジュール名は
ぶつかりません（[パッケージのモジュール](language.md#パッケージのモジュール) を参照）。実行を保存・復元するためのプログラムの識別には、すべてのパッケージのソースが
含まれます（`ModuleCompileResult.sourceFingerprint`）。

コンパイルの前に、`run` は各パッケージのディレクトリを 1 回だけ読み、次の順に確かめます：ディレクトリとそのファイルが印と正確に一致する（足りない・余分な・
変わったファイルが無く、シンボリックリンクや特殊なファイルも無い）。印が `createscript.lock` のパッケージ・版・取得元・SHA-256 を指している。読んだファイル
（印を除くすべてのファイル）からメモリーの中で作り直した正規形のアーカイブが、`createscript.lock` の SHA-256 を持つ。コンパイルするソースは、確かめたバイト列そのものです。
どこかが違えば、何もコンパイルする前に、終了コード 65 で実行を止めます。そのため、印だけを信頼することはありません：ファイルと印を同じように変えても、
ファイルがもうロックファイルのアーカイブを作れないので、見つかります。`run` はネットワークもキャッシュも使わず、ファイルも書きません。

信頼するのはロックファイルです：ファイル、印、`createscript.lock` を一緒に変えたものは、別のアーカイブをインストールしたものと区別できません
（`createscript.lock` の変更は、コードの変更と同じようにレビューしてください）。`.createscript/packages` を消してから `createscript install` をもう一度実行すると、
アーカイブをロックファイルともう一度照らし合わせます。

新しいファイルごとに隣に `._` のファイルを足すファイルシステム（macOS は、FAT と exFAT のドライブや一部のネットワークドライブで、拡張属性を保存するためにこうする）
には対応していません：パッケージのディレクトリが、インストールしたファイルだけを持つ状態でなくなるからです。`createscript install` は、何かを変える前に試しのファイルで
これを見つけ、終了コード 73 で止まります。`run` は、パッケージのディレクトリにあるそのようなファイルを拒否し、理由を示します。

#### ほかの利用者が変えられるディレクトリ

`createscript install` は、何かを変える前に、プロジェクトのルート、その上の `/` までのすべてのディレクトリ、`.createscript` とその下のすべてのディレクトリの、
所有者と権限を確かめます。`createscript run` も、インストールしたパッケージを使う前に同じことをします。リンクはたどりません：ルートの上のディレクトリは
その本当のパスのものを見ます。`.createscript` の中のリンクは、ほかの検査に任せます。ディレクトリを受け付けるのは、それがあなたか `root` のもので、
グループもほかの利用者も書き込めないときです。ほかの人が書き込めるディレクトリを受け付けるのは、プロジェクトより上で、スティッキービットがあり（`/tmp` や
`/Users/Shared` のように）、途中の次のディレクトリがあなたか `root` のものである場合だけです。そのときは、ほかの誰もそれの名前を変えたり消したりできないからです。
グループが書き込めるディレクトリは、ほかの人が書き込めるものとして数えます。グループのメンバーは確かめられないからです。ほかの誰も入れないディレクトリ
（グループとほかの人に `x` が無い）は、それより先を調べません。

ディレクトリが検査に通らなければ、コマンドは終了コード 73（`install`）か 65（`run`）で止まり、何も変えず、そのディレクトリとその権限を示します。
権限を自分で変えることは決してありません：それが望みなら、ほかの人の書き込みの権限を外すか（`chmod go-w <directory>`）、プロジェクトを移してください。
`install` が作るディレクトリとファイルは `rwxr-xr-x` と `rw-r--r--` になる（umask はさらに外すことしかできない）ので、検査に通ります。

限界：アクセス制御リスト（macOS の `chmod +a`）は、Java 21 の標準 API では読めないので、ACL がほかの人に書き込みを許しているディレクトリは見つけられません
（macOS のホームディレクトリには、既定で `deny delete` の ACL が付いていますが、害はありません）。所有者と権限を読めないところ、例えば POSIX の権限の無い
ファイルシステム（例えば Windows）では、パッケージを使う `install` と `run` は推測せずに止まります。そのため、Windows でパッケージをインストールすることは
まだできません。Linux も同じ規則ですが、まだ試していません。この検査で、ほかの利用者がディレクトリを置き換えることはできなくなります。権限を変えられるのは
所有者と `root` だけだからです。あなたとして動くプログラムは止めません。インストール中にディレクトリをシンボリックリンクに置き換えられる問題は、別の問題です（L-5。下を参照）。

インストール中にシンボリックリンクに置き換えられたディレクトリ（L-5）：Java 21 には、すでに開いたディレクトリを基準にして操作する、どの OS でも使える方法が
ありません（macOS では `SecureDirectoryStream`、`openat`、`renameat` が使えない）。そのため、対象をパスで指す操作は、あなたの利用者として動くプログラムが
確かめてから操作するまでの間に `.createscript/packages/<name>`（または途中のほかのディレクトリ）をシンボリックリンクに置き換えると、向き先を変えられてしまいます。
そこで macOS と Linux では、`install` はプロジェクトの中の変更を、[ファイル](#ファイル) の節で説明した補助プロセス（`AnchoredFs`）を通して行います。
Windows では今もパスに基づく確かめ方を使っており、この問題は Windows では解決していません。

記録にある試験（`docs/audits/S8.3-L5-Java21-Assessment.md` の 5.3 と 5.7）では、インストールの間に、同じ利用者の別のスレッドがディレクトリを置き換え、
リンクの先にはインストーラーの名前のおとりのファイルを置きました。

| 試験（`L5RaceTest`） | 環境 | 結果 |
|---|---|---|
| 14 方式 × 300 回 = 4,200 回のインストール。`AnchoredFs` の前 | macOS、Temurin 21.0.12 | プロジェクトの外への書き込み 77 回（ほとんどは空の `.part-` のファイル。中身のあるものは 1 回で、移されたパッケージのディレクトリ） |
| 14 方式 × 300 回 = 4,200 回のインストール。`AnchoredFs` あり | macOS（Darwin 25.3、Apple Silicon）、Temurin 21.0.12 | プロジェクトの外への書き込み 0、既存のファイルの変更・削除 0、誤って成功と報告したインストール 0。置き換えが 1 回だけのインストール 2,100 回のうち 2,092 回が成功し、残りの 8 回は安全でないとして止まった |
| 14 方式 × 60 回 = 840 回のインストール。`AnchoredFs` あり | Linux（Docker の `eclipse-temurin:21-jdk`。`/bin/sh` は dash、GNU coreutils）、Temurin 21.0.13 | 同じくすべて 0。置き換えが 1 回だけのインストール 420 回のうち 420 回が成功 |
| 14 方式 × 60 回 = 840 回のインストール。2026-11-15 の最後の修正の後 | macOS、Temurin 21.0.12 | 同じくすべて 0。置き換えが 1 回だけのインストール 420 回のうち 418 回が成功し、残りの 2 回は安全でないとして止まった |

これらの結果にも、対策そのものにも、限界があります。

- 試験が確かめるのは、試験が実装している置き換え方だけです。`L5RaceTest` は `CREATESCRIPT_L5_RACE=1` のときだけ動くので、CI では動いていません。
  Linux では Docker の中でだけ実行しました。権限の変更が失敗する場合の試験は、macOS だけで動きます。
- 対策の対象は、`install` がプロジェクトの中で行う変更です。プロジェクトの外のキャッシュは、以前の確かめ方のままです。
- インストールの最中に、あるプログラムがインストール自身のディレクトリをプロジェクトの外へ移すと、その後の書き込みは移された先のディレクトリへ行きます
  （中身はインストールしているパッケージと、このインストールの写しで、あなたのファイルではありません）。
- プロジェクトとは、インストールを始めたときに本当のパスにあったディレクトリ（デバイス番号と inode）です。それより前に置き換えられたプロジェクトのディレクトリは、
  そのままプロジェクトとして扱います。
- `install.lock` はパスで開くので、置き換えた先にある同じ名前のファイルを開くことがあります。その中身は変えませんが、そのときロックは効きません。
- 答えない補助プロセスは 60 秒で止め、インストールは失敗します。macOS では、補助プロセスが `/dev/fd` を通して開いたファイルを確かめるとき、一瞬だけ失敗する
  （"Bad file descriptor"）ことがあり、原因は分かっていません。補助プロセスは最大 5 回まで読み直し、それでも読めなければインストールを止めます。そのとき成功とは報告しません。
- あなたの利用者として動くプログラムは、インストーラーを使わずに、プロジェクトのファイルを直接変えられます。ここに書いたことは、それを防ぎません。
  プロジェクトは、あなただけが書き込めるディレクトリに置いてください。

評価の記録は、結果を「これらの前提と限界のもとで macOS と Linux では解決、Windows では未解決、全体としては部分解決」としています（5.5）。
`AnchoredFs` より前の記録：移動の前後の確かめ（S8.2、コミット `c9d98f8`）では、1,200 回のインストールのテストで、パッケージが 92 回プロジェクトの外へ移されました。
S8.3 Phase 8（`docs/audits/S8.3-Phase8-Security-Hardening.md`）では、プロジェクトの外への書き込みが 3,360 回のインストール（8 方式）で 23 回、
4,200 回（プロジェクトのディレクトリそのものを含む 10 方式）で 7 回でした。どの場合も、既存のファイルは変わらず、成功と報告したインストールもありませんでした。

### まだ予定しているもの

- プルリクエストで審査する公式のレジストリ（S8.3、[registry.md](registry.md)）：形式、運営の道具、クライアントはありますが、レジストリのリポジトリ、
  そのメンテナー（少なくとも 3 人が必要）、本番の鍵はまだありません。パッケージは `source: "github:owner/repo"` のままなので、マニフェスト・ロックファイル・
  アーカイブの形式は変わりません。レジストリに無いパッケージも、これまでどおり直接インストールできます。
- 版の範囲と依存の解決（S8.4）。
